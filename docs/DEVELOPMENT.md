# Development notes

Stillword targets **Java 17** (`javac --release 17`) and uses Swing, `java.net.http`, and other JDK APIs. There are no third-party Java dependencies. The executable JAR includes the monastery artwork. The initial development environment was macOS on Apple silicon with Java 25.0.2, yt-dlp 2026.07.04, and Deno 2.9.3; local audio work upgrades the project-local yt-dlp to 2026.08.19 because the older build failed audio downloads with HTTP 403; Java 17 is the compilation target, not a claim that every runtime/OS combination has been tested.

Run commands from the StillWord project directory:

```sh
./build.sh                         # Compile and create build/StillWord.jar
./run.command                      # Rebuild, then open the app
./run.command --demo                # Open with clearly labeled demonstration text
./test.sh                          # Build and run standalone regression tests
./setup-local-ai.sh                # Install/check Ollama and prepare the free local summary model
./setup-local-speech.sh            # Build/check whisper.cpp and the local speech model
java -jar build/StillWord.jar --preview build/preview.png --demo
```

The last command renders the Swing interface to a PNG without showing a native window. Demo text is synthetic; it is neither an extracted video transcript nor an AI response. A rendered preview checks layout but does not replace testing native dialogs and keyboard interaction in the running app.

Caption extraction deliberately improves on global `awk '!seen[$0]++'` deduplication: repeated statements later in a talk are retained. Only matching text in adjacent overlapping or rolling subtitle cues is removed. A lone matching boundary word in otherwise longer cues is preserved so ordinary repetition is not silently lost. Empty display-reset cues prevent deduplication across that reset. Whitespace-only display lines inside a cue are skipped without prematurely discarding the subsequent speech text. Range selection uses cue overlap with `[start, end)` and cannot cut speech at individual word boundaries. Publisher captions are attempted first; automatic captions are requested only when no publisher caption file is found. The configured language must be `en.*` or an English language tag.

`VttParser.parseWithCues` returns a `Parsed` record containing the cleaned text and an immutable list of `Cue(startSeconds, endSeconds, startOffset, endOffset)` records. Offsets are UTF-16 positions in that final text, with an exclusive end. A span covers only the text newly emitted by its source cue after deduplication; a fully duplicated cue emits no span, and inserted spaces or paragraph separators are outside the spans. Selected ranges rebase text offsets while retaining original video times. `parse` delegates to this parser and returns its cleaned text. `TranscriptService.Result` includes the cue list and retains its three-argument constructor for text without timing metadata.

Loaded caption and speech positions are tracked through ordinary transcript edits. A normal click, caret movement, or selection on any timed text updates a visible **▶ Play video at 12:34** button, a passage excerpt, and **Copy link** below the editor; no AI ambiguity flag or keyboard modifier is required. The editing click itself never opens a browser. The button opens the canonical loaded video URL with `&t=Ns`, where `N` is the cue’s start rounded down to a whole second; Copy link copies that exact URL. The full address is also available in the tooltip and accessible description. Changing the URL input does not change links belonging to already loaded text.

`VideoLinks.PlaybackLink` exposes the URI, precise cue start/end seconds, and excerpt. Caret/selection changes notify the UI through its listener, and clicking a gold summary phrase updates the same visible link. Zero-duration cues with a nonempty text span remain valid anchors. Ordinary corrections move the text positions while retaining their source times. Untimed inserted text, a whole-document replacement, or a new document cannot inherit guessed timestamps; the visible link clears or disables when no matching timing remains. **Play passage**, modifier-click (**Command** on macOS, **Control** elsewhere), and **Play video here** remain optional shortcuts.

These links provide cue-level seeking, not word-level alignment. Browser autoplay remains outside the app’s control. Pasted plain text does not establish a timing map. Saving exports UTF-8 plain text only; playback metadata is held in the editing session and is not written into either text file.

Each caption-retrieval yt-dlp invocation has a two-minute deadline, a 20-second socket timeout, limited retries, configuration/plugin isolation, and no media download. Cancelling interrupts the waiting worker and terminates the subprocess. Temporary cleanup is attempted in `finally`; files that cannot be deleted are marked for deletion on JVM exit.

## Local speech recognition

`setup-local-speech.sh` installs under `tools/speech`. It builds whisper.cpp **1.9.4** natively for the current Mac’s `arm64` or `x86_64` architecture, using CMake and Apple’s clang/SDK. CMake and Apple Command Line Tools must already be installed for a source build; missing prerequisites cause a clear error and no global installation. CPU and Metal are enabled, project libraries are static, Metal kernels are embedded, and OpenMP, Core ML, and model-download support inside the CLI are disabled. The script inspects the binary’s linked libraries and rejects dependencies outside macOS system paths. The resulting `bin/whisper-cli` requires no adjacent project dylibs or Metal source files.

The engine archive comes from the official `ggml-org/whisper.cpp` v1.9.4 tag. The large-v3-turbo model comes from the `ggerganov/whisper.cpp` repository linked by whisper.cpp’s official model downloader, pinned to revision `98aa99a0a9db05ae2342309f5096248665f7cba3`. SHA-256 values are checked before installation:

| Artifact | SHA-256 |
| --- | --- |
| `whisper-v1.9.4.tar.gz` | `57e280cee375ab02425b806ad5146b99f6eb9357e3c2b31357c8a6af2e2e44ae` |
| `ggml-large-v3-turbo.bin` — 1,624,555,275 bytes | `1fc70f774d38eb169993ac391eea357ef47c88757ef72ee5943879b7e8e2bc69` |

Setup retains the verified source archive in `tools/speech/downloads` and model in `tools/speech/models`. `bin/build-receipt.txt` records engine version, architecture, build configuration, and binary SHA-256; a matching verified binary is reused. Downloads and builds are staged in a temporary directory, with final files moved into place only after their checks pass. An exclusive setup lock prevents simultaneous installers; cancellation stops the active process tree and removes temporary work and the lock. A force-kill can leave a stale lock, which the script reports rather than starting a second installer. No administrator privileges, login item, service, or global library installation is used.

Audio transcription needs a current yt-dlp: an older installation can retrieve captions but fail audio with HTTP 403. The application prefers `tools/yt-dlp/yt-dlp_macos` when available, while preserving an explicit executable override in settings. The development copy is yt-dlp 2026.08.19. Audio transcription is distinct from caption extraction. It downloads the audio through yt-dlp into an operation-specific temporary directory, converts AAC/m4a to 16 kHz mono PCM with the macOS `afconvert` utility, and runs the local speech engine. For a selected range, Java Sound first clips the WAV to the corresponding PCM frame boundaries; only that clipped audio reaches Whisper. The CLI receives neither `-ot` nor `-d`, because its duration flag allowed a decoding segment to overrun the intended end during a live test. Java restores the original-video offset to returned cue times, clamps cue ends to the selected endpoint, and retains zero-duration text cues that fall inside the selection. Selection does not restrict the initial full audio download. Audio, WAV, and intermediate subtitle output are deleted after success, failure, or cancellation. The model remains installed for future use. This workflow needs neither ffmpeg nor Python.

Speech recognition can still mishear specialized vocabulary, particularly Pali, and can hallucinate speech in quiet sections. It is a fresh audio-based transcript, not a verified correction of captions. Summary styles change presentation and cannot repair transcription errors. The current installation is a development build for this Mac; it does not establish a tested universal binary or minimum macOS release.

Primary sources: [whisper.cpp v1.9.4](https://github.com/ggml-org/whisper.cpp/tree/v1.9.4), [pinned model file](https://huggingface.co/ggerganov/whisper.cpp/blob/98aa99a0a9db05ae2342309f5096248665f7cba3/ggml-large-v3-turbo.bin), and [official model downloader](https://github.com/ggml-org/whisper.cpp/blob/v1.9.4/models/download-ggml-model.sh).

**AI modes**

The Summary panel's model dropdown defaults to **gpt-oss 20B — Free, local**, using OpenAI's `gpt-oss:20b` through Ollama at `http://localhost:11434/v1`. The local alias `stillword-gpt-oss` retains an explicit `num_ctx` of 32,768. That is the server context allocation; local summary processing now uses smaller contiguous source sections instead of one 32,000-character request. The **Set up** button beside that dropdown and `setup-local-ai.sh` invoke the same service. Setup reuses an installed Ollama executable, or downloads a pinned macOS runtime and verifies its SHA-256 before extraction. Before pulling weights, setup checks `/api/show` for `gpt-oss:20b`: an existing base model is reused, so upgrading the alias context makes no pull request and does not duplicate weights. Only a missing base model triggers the roughly 13 GB download. Other server errors fail visibly instead of triggering a download. The runtime itself is roughly 160 MB. Plan for 20 GB free disk and at least 16 GB GPU/unified memory for the base model; 32 GB provides more headroom for the larger context and other applications. The larger context can use more memory and processing time, with performance depending on hardware and workload. See [LOCAL_AI.md](../LOCAL_AI.md) for operating-system requirements, runtime/model locations, environment overrides, and primary sources.

Stillword starts its own server on `127.0.0.1:11434` with Ollama cloud features disabled and stops that owned process on JVM shutdown. It reuses an already-running Ollama server without changing or stopping it. Model readiness includes checking the alias's context setting; a short or missing setting requires setup instead of accepting the server's potentially smaller default. Setup can be cancelled and resumed. No administrator password, login item, or system service is installed by this workflow.

The dropdown's **ChatGPT — Free / subscription** and **Claude**, **Gemini**, **Copilot**, and **Perplexity — Your plan, browser** choices use a manual website handoff. **Prepare prompt** builds a prompt with the complete edited transcript and editorial guidance. **Copy & open AI** copies it and opens the selected website; **Copy prompt** only copies it. The user selects an available model and submits the prompt in the website, then imports the answer with **Paste summary** or normal paste. The application does not automate sign-in, model selection within a website, submission, or response retrieval. Website model availability, free access, subscriptions, and limits are determined by the user's account. Other HTTPS sites are accepted through **Custom AI…**. URLs cannot contain credentials, fragments, unsupported control characters, or invalid ports. The transcript is never put into the website URL. Browser prompts use JSON to distinguish source material from user guidance, preserve Unicode and embedded marker text, and avoid silent truncation. [AI-PROVIDERS.md](AI-PROVIDERS.md) records references and the distinction between browser accounts and direct APIs.

**GPT-6 Luna — Fees, API** and **GPT-5 — Fees, API** select paid OpenAI API models; ChatGPT website subscriptions do not pay for these API requests. Choosing **Custom AI…** opens settings for OpenAI-compatible Chat Completions, Anthropic Messages, another website, or a local server. The settings connection labels are **Local model — Free**, **AI website — Free / subscription**, and **AI API — Fees may apply**. Endpoint, model, protocol, and session-only key are user-configurable; the OpenAI preset uses `gpt-6-luna`. The editable API model dropdown shows fee labels in its list but edits/stores/sends the raw model ID, including arbitrary provider-specific IDs. Choosing an item changes configuration only and makes no AI request. Switching an API endpoint or protocol clears its key; switching models on the same connection retains the key. API and local configuration are stored separately. Standard OpenAI configuration may obtain a key from `OPENAI_API_KEY`; no key is persisted to Preferences.

**Summary requests**

Local OpenAI-compatible gpt-oss uses `LocalSummarySections`, `LocalSummaryWriter`, and `LocalSummaryStream`. Source text is separate from trusted system instructions. The input guard remains 800,000 characters; guidance is limited to 4,000 characters. Character limits are UTF-16 code units, not token counts.

Boundary detection reads windows of at most 24,000 source characters, represented by numbered spans of at most 400 characters. It returns proposed question/topic starts with verbatim anchors. The application resolves these against the actual source, then creates contiguous sections of at most 6,000 characters. Every original character is retained in order. Anchors of 3–24 words match case-insensitively with whitespace normalization within the indicated span and up to 800 characters on either side, clipped to the current window. Repeated anchors use the earliest local match. Unmatched hints are skipped individually; malformed response structures or invalid span IDs use a deterministic paragraph/whitespace split. These boundaries organize text and never determine playback times. Network and cancellation failures propagate instead of triggering more requests. Short sections below 1,000 characters are joined forward within the 6,000-character bound, keeping brief introductions and restatements with their answers without discarding text.

Each section receives the selected style and user guidance and produces one summary draft. The app assembles those drafts in source order, with no final global AI rewrite that could erase an earlier answer. Boundary detection uses low reasoning and 1,200 output tokens. Ordinary drafts use low reasoning and 1,800 tokens; an explicit first-person statement of not knowing, understanding, or explaining triggers medium reasoning with 3,200 tokens. These budgets include reasoning. Temperature is zero. Model-reported truncation is an error, never an accepted partial summary. Simple generated Markdown heading/bold styling is removed while exact `[[check: …]]` markers are preserved. This processing does not verify the truth of the model's claims; generated summaries remain editable drafts.

The earlier ten-minute failure occurred while the local model was still generating: the source fit its 32K context and all model layers used Metal. The large reasoning/output allowance, combined with observed transient memory pressure, made a single whole-transcript request exceed its deadline. Splitting the source and bounding each completion reduces that workload; streaming distinguishes active generation from a stalled connection. It does not make the model semantically reliable.

The fetched video title is classified by `SummarySource` as lecture, Q&A, or unknown; raw titles never become trusted prompts. Lectures receive topical-summary instructions, including when the speaker asks rhetorical questions or Detailed is selected. Only explicitly identified Q&A videos receive Q&A-focused instructions. Title-free pasted sources default to topical prose unless they clearly establish an audience Q&A session. This context is passed to boundary detection, section drafts, API notes/reduction/final requests, and browser prompts. Ordinary corrections retain the loaded format; replacing the entire transcript resets it to unknown. Actual audience exchanges retain question/answer distinctions without turning a lecture into Q&A. An empty AI final answer is never treated as an intentional omission. The writer retries that same section once with its source, style, guidance and token budget intact and an explicit final-answer reminder. Persistent blank or malformed omission output fails the whole request rather than publishing a partial summary. Legitimate whole-section omissions require an exact `[[omit:filler]]` or `[[omit:excluded]]` response; the latter is invalid with blank guidance. Transport errors and cancellation are not retried. If all sections are explicitly omitted, the message describes the model's classification rather than claiming the user removed all content.

Local responses stream through SSE with a 120-second inactivity limit, an eight-minute overall limit per request, a 20-second connection timeout, and a 1 MiB stream limit. The status shows the phase and elapsed seconds about every two seconds, including during model loading. These limits apply per request, not to an entire long talk. Private reasoning and partial generated text are not displayed in the Summary editor. A valid finish status and completion marker are required. Cancellation closes network resources, and failure/cancellation preserves existing panel text.

Other providers keep the ordinary 24,000-character section-and-reduction path, a two-minute remote request deadline or ten-minute deadline for custom loopback services, and a 1 MiB response limit. OpenAI requests use `max_completion_tokens`; compatible providers and Anthropic use `max_tokens`. The ordinary allowance is 3,000; applicable remote reasoning models receive 8,192. Anthropic uses a separate system field, `x-api-key`, and the Messages API. Remote connections require HTTPS; HTTP is accepted only for loopback. Redirects are disabled, provider errors redact credentials, and failed paid API requests are not automatically retried.

Auto adapts length to the source; Brief requests a compact overview; Detailed preserves questions, answers and supporting detail, or topical structure when no actual Q&A exists. Every style remains manually editable. Switching styles preserves manual edits and marks a tracked summary stale; it does not regenerate or replace text. Save writes the current editor contents. Redo summary uses the current transcript, guidance, style and provider and asks before replacing unsaved text. All editors re-enable when the worker finishes, fails, or is cancelled. No style imposes a page cap or word-count rewrite loop.

Uncertainty markers `[[check: exact source phrase]]` become gold links only when the phrase matches timed transcript text. These are optional review suggestions, not a complete error detector. Normal clicks anywhere in a retrieved transcript independently reveal its video-at-this-time link. The user can review the video, edit the transcript, and redo the summary. In browser mode the same workflow uses Prepare prompt, manual submission, and Paste summary. Directly replacing summary text clears its previous provenance instead of claiming it still matches an earlier source.

**Manual timestamp and correction review**

This checklist describes checks to perform in the running app; it is not a claim that these interactions have already passed live verification.

1. Load a video transcript. Click any word normally and verify that **▶ Play video at…**, its excerpt, and **Copy link** update without opening a browser. Click the visible link and verify that YouTube seeks to the corresponding cue; press Play if needed. Copy the link and check its video ID and timestamp. Repeat with text selection, keyboard caret movement, **Play passage**, **Command/Ctrl-click**, and **Play video here**.
2. Insert or remove text before a later timed passage, then play that later passage again. Confirm that ordinary edits have moved its text positions without changing its source video time. Check a passage after a paragraph break and one containing non-ASCII text.
3. Extract a selected time range and play a passage from it. Verify that the video time refers to the original full video, rather than restarting at zero for the extracted text.
4. Produce or import a summary containing `[[check: an exact phrase from the transcript]]`. Verify that a mapped phrase is gold and clickable and opens the appropriate source cue. Try a phrase absent from the source; it must not acquire an invented timestamp. Review repeated phrases carefully because exact text alone may identify more than one occurrence.
5. Correct the transcript after listening to the video. Confirm that the current summary shows the stale indicator. Choose **Redo summary**, checking that the current correction and guidance reach the currently selected AI and that a successful replacement clears the stale state. Check that a failed or cancelled request retains the existing panel text.
6. For browser mode, choose **Prepare prompt** after an edit, inspect the updated prompt, then submit it manually and use **Paste summary** for the answer. Verify that an exact marked phrase receives the same review behavior. Replace the Summary panel by normal paste and verify **source not tracked**, without inheriting provenance from an older answer. Use the dedicated **Paste summary** button for marker import and source tracking. Website submission is a separate manual action.
7. Paste a transcript with no timing metadata and verify that the visible link and Copy link are disabled rather than implying a reliable source timestamp. Replace or heavily rewrite loaded text and check that any remaining links are appropriate before relying on them.
8. Edit both panels and save them to chosen filenames and directories. Open the saved files in a plain-text editor; verify UTF-8 text preservation and the absence of persisted clickable-link metadata. A saved text file alone does not restore its caption timing map.
9. Review a long Q&A with section-exclusion guidance. Try Auto, Brief, and Detailed; confirm that each changes presentation appropriately, Detailed retains substantive answers, and excluding a later practice section does not silently discard earlier answers about that topic. Gold phrases may be absent; their absence does not establish that the transcript is unambiguous.
